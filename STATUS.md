# J604 bring-up status (MacBook Pro 14-inch, M4, 2024)

Board `apple,j604`, SoC `apple,t8132` (M4, 4 performance + 6 efficiency cores, 10-core GPU, 16 GB). Last updated 2026-11-12.

## How to read this page

- **Working**: measured on this Mac, with the date of the measurement.
- **In progress**: code exists (in our kernel, boot loader or packages) or part of it runs, but the block is not yet measured working end to end.
- **Not started**: no code yet.
- Every row carries an evidence label and a date:
  - **MEASURED** (date): run on this Mac.
  - **INFERENCE** (date): our reasoning, not a measurement.
  - **TO-VERIFY** (date): open question, or a claim not yet checked on the current build.
- A driver that loads, or a device that appears, is not a pass on its own. Where that is all we know, the row says so.
- "Current build" means the packages listed below, installed on 2026-11-09.

- Deep sleep (suspend to RAM): **In progress, not working.** On 1.848 (2026-11-12) the first two real-sleep runs of the T8132 sequence did not come back: both were reset by the 5 s watchdog at the sequence's last step (MEASURED). The fix in 0338 (1.850, off by default) did not change this: two runs on 1.850 with its switch on ended the same way (MEASURED 2026-11-12). On 1.850 the four power-gate words the boot firmware describes read 0, and none keeps a plain write from user space while the machine is awake; a run with all four written in the boot that went to sleep ended the same way too (MEASURED 2026-11-12). 1.854 can write them from the kernel at the start of the sleep (0350-0353, off by default). In that run on 1.854 the words did not hold, and the machine reset the same way, so the power-gate words are ruled out as the cause (MEASURED 2026-11-12). The cause now found (2026-11-12): on the J604's current boot path (m1n1 started directly) the per-core deep-sleep enable register (`S3_5_C15_C6_2`) reads 0 on all ten cores and refuses any write. A single write, even of the value it already holds, resets the whole machine: twice, both times awake with no sleep attempted (MEASURED 2026-11-12). The T8132 sequence writes that register on every core after the sleep's commit (CODE), which fits every reset of the real-sleep runs (INFERENCE until a sleep gets past that write). Deep sleep on the J604 is being moved to Aurora's aura boot path; whether that lifts the lock here is TO-VERIFY.
